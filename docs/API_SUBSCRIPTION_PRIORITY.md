# OpenAI API 渠道参与订阅优先调度

管理员可在「账号管理 → 新建 / 编辑 OpenAI API Key 账号」的优先级设置下开启
**参与订阅优先调度**。默认关闭，现有账号保持原来的调度行为。

开启后，在全局「高级调度」和「订阅优先」均启用时，该 API 渠道与 ChatGPT
订阅账号一起进入优先候选池。未开启的 API 渠道仍在常规候选池中回退使用。
新增渠道只需设置此开关，无需再增加账号 ID 白名单或代码分支。

## 行为边界

- 只适用于平台为 `openai`、类型为 `apikey` 的账号。
- 只改变候选池归属，账号仍使用原 API 地址、API Key 和协议转发。
- `plan_type` 标签不授予此能力；此开关也不会把 API Key 识别为真实 OAuth 订阅。
- 开关属于账号，对该账号所属的所有分组生效，包括只有 API 渠道的分组。
- 分组、模型支持、可调度状态、并发、限流和原有评分规则继续生效。
  优先池先于常规池尝试选号；账号的数值优先级在各自池内比较。
- 进入优先池不等于独占流量或平均分流。最终选号仍由优先级、负载、
  Top K 等现有规则决定；已有粘性会话继续遵守原有绑定规则。
  若 Top K 内的候选获取并发失败，仍可能回退到常规池，
  不承诺先遍历优先池内所有账号。
- 全局订阅优先关闭时，此开关不改变普通调度。计费、余额和额度逻辑不变。

## 管理 API

使用账号现有的 `extra` JSON 字段，不需要数据库迁移：

```json
{
  "extra": {
    "openai_subscription_priority_enabled": true
  }
}
```

这是字段示意，自动化更新应先读取账号，保留已有 `extra` 中的其他配置，
再使用现有账号更新接口提交。仅 JSON 布尔值 `true` 开启；
缺省、`false` 和字符串 `"true"` 均不开启。关闭时明确保存 `false`。
管理接口继续使用原有管理员权限。

该字段保留在调度缓存的元数据中，账号更新通过原有缓存刷新机制生效。
回退可关闭账号开关；回退服务版本时，旧版本忽略此字段，无需回滚数据库。

若多实例共用调度 Redis，先将调度实例统一升级，再开启账号开关。
旧版本写入的缓存投影不保留此字段，混跑期间可能暂时退回普通调度。
